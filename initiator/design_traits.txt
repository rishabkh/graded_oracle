# Design traits: how real hardware is written, which our designs were not
# (21 Oct 2026, Rishab approved). One line is drawn per design, in balanced
# turns like the other seeds; a repeated line weighs more. 26 lines.
#
# Measured 15 Oct 2026 over 560 modules of open-source hardware (PULP
# common_cells, lowRISC Ibex, OpenTitan prims and peripherals, alexforencich
# verilog-axis and verilog-axi, ZipCPU wb2axip), against our 252 newest
# designs:
#   valid/ready handshake    49% of real modules       6% of ours
#   asynchronous reset       21% (Ibex 77%)            0% of ours
#   enum for named states     5% (Ibex 20%)            0% of ours
#   parameters               87%                       about 40% of ours
#   initial blocks           37%                       81-91% of ours
# and no design of ours ever loads a register from an input (a limit, a
# starting value, a configuration), so its value at any moment is unknown
# to the proof.
# Parameters are a rule in the generator prompt (prompts.py), not a trait
# here. Initial values stay on every register on purpose: our proofs need
# them.
#
# Loaded registers, measured 22 Oct 2026 on fresh copies of the same 560
# modules (the shares above came out close: asynchronous reset 23%
# against 21%, enum 5%, parameters 87%). The rule: a register counts as
# loaded from an input when its next value reads input ports and nothing
# else but constants, written in the clocked block, in the next-value
# signal the block copies (q_q <= q_d) or in a PULP register macro, and
# the load sits under a reset or under a condition that names a load,
# start, set, init, seed or configuration signal. 20 of 560 modules
# (3.6%) do it, none of them at reset; counting registers written on a
# write strobe too (we, wr, write), 43 (7.7%); counting every register
# loaded straight from an input, plain data capture included, 182 (32.5%).
#
# Weights (23 Oct 2026, Rishab chose the measured shares): a valid/ready
# handshake on half the designs (49% of real modules); an asynchronous
# reset on 3 in 13 (23%, the 22 Oct count on the fresh copies); named
# states on 3 in 13, which follows Ibex (20%) rather than the 5% of all
# 560 modules; a register loaded from an input on 1 in 13 (7.7%, the share
# that counts write-strobe loads). This replaces the 1 in 3 chosen on
# 21 Oct after the 10 Oct 2026 analysis of the trained model's mistakes,
# which no real-design number supported. Plain synchronous style on the
# rest. The two choices are crossed, so a line carries at most a handshake
# and one other trait:
#                       async reset  named states  loaded register  plain
#   with a handshake         3            3              1            6
#   without one              3            3              1            6
# The asynchronous-reset lines also say the property, its guard and the
# invariants never read rst_n (22 Oct 2026, review finding): our checker
# and EBMC 6.0 disagree about a register's value while the reset is held,
# so a property that reads it can be proven by one and refuted by the
# other.
valid/ready handshake and asynchronous reset: give the main input or the main output a valid/ready handshake with back-pressure: an item moves only on a cycle when valid and ready are both high; as the sender, the design holds valid and its data steady until the item moves; as the receiver, it lowers ready when it cannot take more instead of dropping data. With the incoming valid and ready held low nothing moves: that is the idle condition. Also reset the state with an asynchronous active-low input rst_n, written always @(posedge clk or negedge rst_n) with if (!rst_n) first; every register keeps its initial value as well, and with rst_n held high the idle condition must still leave all state unchanged. The property, its guard and the invariants never read rst_n: they say what holds in normal operation, not while reset is held.
